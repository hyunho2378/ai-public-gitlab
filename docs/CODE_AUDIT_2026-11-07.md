- M7_owner_C.md는 검사 시 존재하지 않아 원장 담당 항목을 처리하지 못했다.
- 코드 data-figma 이름표 기반 대응표를 생성했다. 실제 Figma 컴포넌트 실물 연결은 검증하지 않았다. 미등록 부품을 임의로 일치한다고 표시하지 않는다.

- 현황판 기존 열지도는 작은 폭에서 내부 가로 스크롤이 있다. 문서 가로 넘침 0과 별개다.
- 리빌딩 기존 다른 CSS의 알약/선/단독 버튼 패턴과 1279/1199/768 등 미디어 기준 전수 정리는 남았다.
- 서버 코드 전수 검수, 중복 패턴 추가 추출, 모든 라우트 회귀는 미완료다.

### 부모 지적 캡처 재검증

새 탭 1440에서 dark/light 모두 검색 344×32(x548), 판 x248 y72 w1184 h820, 반경12, 바깥 여백8이다. 두 모드의 layout 변수 누락은 0이다. 판 선은 border가 아니라 inset box-shadow이다. 이전 폭 변경 직후 캡처와 안정 상태가 달랐으므로 이전 캡처를 정상 증거로 사용하지 않는다. 밝은 검색 면만 dark gray95로 고정돼 대비가 나빴으므로 light 선택자 안에서 면과 글자색만 수정했다.

70개 라우트를 실제 공개 kordoc 저장 자료(프로젝트150, fixture=kordoc)로 1440/360 순회했다. 문서 가로 넘침, 빈 main, pageerror 0. 360 console error 0. 인증 화면/빈 데이터 상태도 정상 화면으로 센다. API 업무 기능 전체 검증과는 다르다. 상세 JSON은 세션 tmp routes-1440.json / routes-360.json이다.

### 최종 회귀 수치

- 수정 뒤 70라우트 × 1440/360 = 140조합: 문서 가로 넘침0, 빈 main0, 콘솔 오류0, pageerror0 (`routes-final-140.json`).
- 아이콘 가운데 실패는 커밋 목록 최근검색 / 작업항목 더보기 2종이었다. 공통 Menu가 아이콘 단독 버튼에도 자동 꺾쇠를 붙인 것이 원인이다. `toggle && !btnClass.includes('rb-iconbtn')`로 바꿨고 두 화면 360 재검사에서 dx/dy0, 짝수 크기를 확인했다. 1440 커밋 목록도 dx/dy0이다. 전체 UI 요소 대비 전수 검사는 아직 아니다.
- 밝은 검색 단추 대비 16.18:1. 첫 화면 IconButton 20개 dx/dy0.
- dark 전후 4개 뼈대 상자(상단 바, 검색, 사이드바, 판)의 x/y/w/h와 배경색 JSON 완전 일치 (`dark-geometry-regression.json`).
- 밝고 어두운 1440 안정 캡처: 세션 tmp `light-1440-after-fix.png`, `dark-1440-after-fix.png`. 이전 `rebuild-light-1440-final.png`는 폭 전환 직후 불안정 캡처이므로 폐기한다.
- 현황판 잔여 px 검색은 공식 미디어 구간4행뿐이다. 직접 색0. 앞서 수정한 직접 크기/장식선 후보는 해결됐다.
- 원장 M7_owner_C.md는 최종 검사 시점에도 없었다. 실제 Figma 실물 대응, 서버 검수, 전체 요소 대비 전수 판정은 남는다.
