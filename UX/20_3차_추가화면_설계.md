### 1-3. 화면이 읽는 카드 칸(김민우 `build.mjs` 출력 제안)

현재 `app/public/data/cards.min.json` 칸 이름 유지, 아래 칸만 추가. 최종 이름은 김민우와 장준호 확정(결정 필요 1).

- `meta.dataVersion`: 검수한 자료 버전 글자(예 `2026-10-30-r1`), metrics.json과 같은 값
- `meta.fetchedDate`: 수집일(기존 칸), 화면의 "수집" 날짜
- `meta.count`: 수집 대상 고유 프로젝트 수(기존 칸), 생성 실패 포함
- 항목 칸 `b`: 항목별 근거, 값 `readme`(README 기반), `code`(코드 추정), `none`(정보 부족). 대상 항목 `oneLine`, `form`, `license`, `run`, `limits`
- 항목 칸 `e`: 근거 위치(기존 칸). README는 `{lines:[시작,끝]}`, 코드 추정은 `{paths:[...]}`
- 카드 칸 `basis`: 대표 근거, `oneLine.b`와 같은 값. 생성 실패 카드는 `none`
- 카드 칸 `status`: 카드 생성 상태, 값 `ok`(근거 있는 항목 1개 이상), `thin`(처리 완료, 모든 항목 정보 부족), `failed`(생성 처리 실패)
- 카드 칸 `readme.v`: README 원천 상태, 값 `present`와 `template`(둘 다 화면 "있음"), `none`(없음 확인), `unknown`(미확인, 원문 접근 실패 포함)
- 카드 칸 `fields.v`: 확정 주분야 하나(글자), 확정 전이면 null
- 카드 칸 `fields.check`: true면 분류 확인 필요. `fields.v`가 null이고 check가 없으면 미분류
- 카드 칸 `desc`, `stars`, `forks`, `lastActivity`, `createdAt`, `org`: 목록용 칸(팀 역할 문서 3장 ③)

## 2. 근거 표시 3종과 상태 표시

### 2-1. 목적

- 목적: 같은 프로젝트의 근거와 상태를 목록 행, 검색 결과 행, 소개 카드에서 같은 모양으로 표시

### 2-2. 표시 규칙

- 대표 근거: 카드 `basis` 값 하나, 하는 일 항목 기준. 목록 행과 검색 결과 행은 대표 근거만 표시
- 항목별 근거: 소개 카드 다섯 항목마다 `b` 값 표시. A-02 본문 카드에서만 다섯 개 모두 표시
- 카드 생성 상태: 정상 생성은 표시 없음(근거 표시만), 자료 부족과 생성 실패만 하는 일 줄 자리에 글자로 표시
- README 원천 상태: A-02 카드 머리 줄에만 표시, 목록에는 표시 없음
- 분야 상태: 목록 행 주제 줄 맨 앞 태그, A-02 카드 머리 줄, 오른쪽 정보 열 주제 옆 태그(기존 extra-field 자리)
- 배지 개수 한도: 한 행에 KRDS badge 하나(근거 표시). 분야와 상태는 글자와 태그(UX/14 3-1 배지 더미 금지)

### 2-3. Feedback/Basis badge 속성

- Figma 구성: KRDS badge(361:44254) 인스턴스 하나를 품은 세트, Size=medium(높이 24, 모서리 small2 4), 알약 모양 아님
- 속성 Basis: variant, 값 Readme, Code, None
- 속성 Label: text, 기본 글자 아래 표 그대로
- 코드 props: `basis`(readme, code, none), `title`(마우스 올림 풀이)

| Basis | 화면 글자 | KRDS badge 속성 | 코드 클래스 | 마우스 올림 풀이(title) | 키 |
|---|---|---|---|---|---|
| Readme | README 기반 | Type=solid, Color=primary | `krds-badge medium bg-primary` | README 원문 근거 | `B_readme`, `B_readmeTip` |
| Code | 코드 추정 | Type=solid, Color=secondary | `krds-badge medium bg-secondary` | 설명/파일 목록/주요 코드 추정 | `B_code`, `B_codeTip` |
| None | 정보 부족 | Type=solid-pastel, Color=tertiary(코드 gray) | `krds-badge medium bg-light-gray` | 확인 근거 없음 | `B_none`, `B_noneTip` |

- 색 근거: primary 50과 secondary 70은 KRDS 원색 채움에 흰 글자, None은 회색 면(gray 10)과 text/subtle 글자(D-15 회색 예외)
- 대비 확인: 세 변형 모두 글자 대비 4.5:1 이상인지 구현 뒤 측정, 미달이면 결정 필요 2로 올림
- 금지: `bg-light-primary` 같은 연한 채움 변형, `outline-*` 변형(장식 테두리)

### 2-4. 카드 생성 상태 표시

| 상태(`status`) | 근거 표시 | 하는 일 줄 자리 글자 | 모양 | 키 |
|---|---|---|---|---|
| ok 정상 생성 | 대표 근거 그대로 | 하는 일 값 | 본문 2단계 | 없음 |
| thin 자료 부족 | 정보 부족 | 소개 자료 부족 | 본문 2단계, text/subtle | `S_thin` |
| failed 생성 실패 | 정보 부족 | 소개 생성 실패 | KRDS 경고 아이콘(sys_warning) 16과 글자, warning 글자색, 채움 없음 | `S_failed` |

- 자료 부족과 생성 실패 카드도 이름과 원문 연결 유지
- 생성 실패 글자를 사실 정보처럼 하는 일 값 칸에 기재 금지, 오류 원문 비공개

### 2-5. README 원천 상태 표시

| `readme.v` | 화면 글자 | 키 |
|---|---|---|
| present, template | README 있음 | `R_present` |
| none | README 없음 | `R_none` |
| unknown | README 미확인 | `R_unknown` |

- 모양: 글자 하나(라벨 없음, 본문 3단계, text/subtle), 아이콘 `ext/file-text` 16

### 2-6. 분야 상태 표시

## 3. 목록 행과 검색 결과 행(Layout/Project row 확장)

### 3-1. 목적

- 목적: 공공 깃랩 탐색 행 구조 유지, 하는 일과 분야, 근거만 추가

### 3-2. 배치 순서(Kind=Explore, `/`)

1. 유형 아이콘, 아바타 32(기존)
2. 제목 줄: 만든 곳 / 이름, 공개 아이콘, Feedback/Basis badge
3. 하는 일 줄: 카드 하는 일 한 줄 말줄임. 카드 없음이면 원문 설명 두 줄(기존). 자료 부족과 생성 실패는 2-4 글자
4. 주제 줄: 분야 태그, 주제 3개, 더보기(기존)
5. 오른쪽: 별표, 포크, 머지 리퀘스트, 작업 항목, 업데이트됨(기존)
6. 점 세 개 메뉴: 이름(상세), 공공 깃랩에서 열기(기존)

- 원문 설명 위치: 카드가 있으면 하는 일이 설명 줄 자리 차지, 원문 설명은 행 `title`과 A-02 정보 열
- 행 높이: 기존 측정값 유지, 하는 일 한 줄 기준, 설명 두 줄 행 이하 높이

### 3-3. 부품과 속성

- Figma: Layout/Project row, Kind=Explore, Density=Regular, Layout=Row(1440) 또는 Stacked(360), Data=Ideal/Min/Max, Show topics=True
- 새 boolean: Show basis(True 기본), Show field(True 기본)
- nested: Feedback/Basis badge
- 코드 props 추가: `card`(카드 객체, 없으면 기존 동작), `kind`(explore, recommend, similar), `reason`, `similarity`, `diff`

### 3-4. 폭 1440과 360 차이

- 1440: Layout=Row, 오른쪽 개수 열 유지, 하는 일 한 줄 말줄임
- 360: Layout=Stacked, 개수 열은 하는 일 아래 한 줄, 하는 일 두 줄까지 균형 줄바꿈 후 말줄임, 근거 표시는 제목 줄 끝(제목이 두 줄이면 둘째 줄 끝)

### 3-5. 구현 담당과 파일

## 5. `/search` 두 탭(F1, F4)

### 5-1. 목적

- 목적: 업무 문장과 만들려는 기능 설명 두 입력 목적을 같은 검색 화면에서 구분, 실제 수집 자료 결과와 근거 표시

### 5-2. 배치 순서(1440)

1. 기존 화면 머리와 경로
2. Navigation/Tabs: 업무로 찾기, 만들려는 기능 설명하기(탭 아래 내용 전체가 탭 패널)
3. 입력 목적 줄: 본문 3단계 한 줄(탭마다 다름)
4. Input/Task search: 입력칸, 검색 버튼, 입력 기준 줄(오류 줄 겸용)
5. 예시 검색어 줄: `예시 검색어` 라벨과 링크 2개(누르면 입력칸 채우고 실제 검색)
6. 본문 두 열(기존 구조)
   - 왼쪽 열(rb-s-side, 기존): 검색 범위 목록, 업무 분야 fieldset(새로), 아카이빙됨 fieldset, 적용 버튼
   - 오른쪽 결과 열(rb-s-results)
     1. 조건 줄: 검색어, 분야, 자료 기준, 조건 초기화
     2. 안내 줄(Feedback/Status block State=Notice): 대체 검색, 자료 기준 불일치, 분야 조건 전환일 때만
     3. 탭별 결과 묶음(5-5, 5-6)

- 주소 값: `q`(검색어), `mode`(task, build), `field`(확정 분야 쉼표 묶음). 상세에서 돌아오면 세 값으로 입력, 탭, 분야 복원
- 검색 범위 목록의 작업 항목, 머지 리퀘스트, 마일스톤, 사용자들: 기존 그대로(공공 깃랩 원문으로 이동), 두 탭은 프로젝트 범위 안에서만 동작

### 5-3. 부품과 속성

- Navigation/Tabs: Tab item 2개, Selected=True/False, Show count=False, Label 탭 이름. 코드 `Tabs` 내보내기(1-2), 이름표 `search-mode-tabs`
- Input/Task search: State=Default/Hover/Focus/Error/Busy, Show value, Placeholder, Value, Hint. nested Action/Button(primary, small, Label 검색). 코드 props `value`, `onSubmit`, `error`, `busy`, `placeholder`, `hint`, `max`(500)
- 업무 분야 fieldset: 기존 아카이빙됨 fieldset 마크업 복제, `krds-form-check` 체크박스, 확정 분야만(분류 확인 필요와 미분류 제외), 이름표 `field-filter`
- 조건 줄: 일반 프레임, 라벨 글자(본문 3단계 굵게)와 값(본문 3단계), 쌍 사이 16, 구분 기호 없음, 이름표 `search-conditions`
- 조건 초기화: Action/Button Type=text Size=small
- 안내 줄: Feedback/Status block State=Notice, Icon(sys_info 16), Message, Show action(다시 시도 링크), 회색 면 surface/gray-subtle, 높이 32, 안쪽 0 12, 모서리 4, 테두리 없음
