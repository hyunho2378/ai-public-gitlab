### 안 1. 원문 줄 근거 체계

- 한 줄 정의: 공공 깃랩의 모든 AI 문장 끝에 "원문 어디에서 왔는지"를 줄 번호와 파일 경로로 붙이고, 누르면 그 줄로 바로 가는 체계

- 우리만의 지점(해석): 다른 AI 검색은 "어느 사이트"까지, 우리는 "어느 저장소 README 몇째 줄"까지. 이미 카드 자료 `e` 칸에 줄 범위와 경로가 있어 새 자료 없이 가능
- 첫 화면(`/`): 정렬 줄 왼쪽 자료 기준 줄 옆에 근거 범례 한 줄(README 기반, 코드 추정, 정보 부족 세 배지와 뜻), 목록 행 근거 배지는 UX-020 그대로
- 검색 결과(`/search`): 추천 이유 글자 끝에 근거 표식 `README 3~5줄`(본문 3단계, text/subtle, 링크), 추천 5개 묶음 아래 `근거 원문 5건` 접힘(KRDS 아코디언 line), 펼치면 프로젝트마다 원문 인용 2~3줄과 줄 번호
- 소개 카드(`/projects/:id/about`): 머리 줄에 작성 주체 문장(예: `수집 README로 생성한 소개, 2026. 10. 30. 수집`), 항목마다 근거 줄, 근거 줄을 누르면 아래 README 원문 구역의 해당 줄로 이동하고 그 줄 배경을 gray 10으로 1.2초 강조 후 원래대로
- F4 비교: 비슷한 프로젝트 행의 차이 줄 끝에도 같은 근거 표식
- F5 MCP: 응답 글자에 같은 표식 문자열(`근거: README 3~5줄, 링크`)을 넣어 AI 코딩 도구 안에서도 같은 체계
- F6 현황판: 지표 C 하는 일 근거와 연결, 범례와 같은 이름
- 모션: 근거 줄 누름 시 해당 줄로 부드러운 이동과 강조만, 장식 모션 없음
- 장점: 기획안 F2 완료 기준(원문 위치 연결, 정보 부족 표시)과 1대1, 자료 칸 이미 존재, KRDS 부품만 사용, 심사와 시연에서 "근거를 눌러 원문을 확인하는 장면"이 한 번에 보임
- 단점: 근거 표식이 많은 화면에서 글자 밀도 증가, 줄 강조 이동은 README 렌더러에 줄 번호 앵커 추가 필요

- 단점: 해석 줄 생성에 AI 함수 출력 칸 추가 필요(분야, 핵심어), 해석이 틀릴 때 문구 설계 부담, F1 응답 시간 증가 가능
- 구현 난이도: 중상. 검색 함수 응답 형식 변경(한은진, 김민우 협의), 좁히기 문구 생성 규칙

### 안 3. 두 층 소개 카드(업무 담당자 층과 개발자 층)

- 한 줄 정의: 같은 프로젝트를 업무 담당자 말(무엇을, 누가, 어떤 조건에)과 개발자 말(실행 형태, 실행 방법, 의존성, MCP 호출)로 두 층 보여 주고 KRDS 탭으로 전환
- 레퍼런스 근거: KRDS 시작하기 역할 탭, Hugging Face `Use this model` 코드 패널, Notion 역할별 예시
- 우리만의 지점(해석): KRDS 사이트 자체가 쓰는 역할 탭 문법을 서비스 안 소개 카드에 적용
- 첫 화면(`/`): 머리 오른쪽 `보기 방식 업무 담당자 / 개발자` 선택, 목록 행 하는 일 줄 문구가 층에 따라 바뀜
- 검색 결과: 업무 담당자 층은 추천 이유 중심, 개발자 층은 실행 형태와 언어 메타 중심, F5 MCP 연결 안내는 개발자 층에만
- 소개 카드: 다섯 항목을 두 탭으로 나눔(업무 담당자: 하는 일, 이용 조건, 한계 / 개발자: 실행 형태, 실행 방법, 근거 경로)
- 장점: 두 퍼소나 요구를 한 카드에서 해결, F5 위치가 분명
- 단점: 카드 자료에 층별 문구가 없어 생성 단계 추가 필요, 같은 사실이 두 번 쓰여 불일치 위험, 상태 수가 두 배
- 구현 난이도: 상. 카드 생성 도구 변경과 문구 검수량 증가

## 4. 추천안

- 추천: 안 1 원문 줄 근거 체계
- 이유 1: 기획안 F2 완료 기준(근거 있는 항목의 원문 위치 연결, 정보 부족 표시, 생성 상태 구분)을 화면 동작으로 직접 보여 줌
- 이유 2: 카드 자료 `b`와 `e` 칸이 이미 설계되어 새 자료 생성 없이 화면 규칙만 추가
- 이유 3: 확인한 AI 검색 서비스(Perplexity, ChatGPT search, Claude) 모두 출처를 사이트 단위로만 표시, 줄 단위 원문 연결은 Elicit 외 사례 드묾(확인 범위 안)
- 이유 4: 목록과 검색, 소개 카드, MCP 응답, 현황판까지 같은 이름과 같은 표식이 흐르는 시스템 차원 변화
- 이유 5: KRDS badge와 아코디언, 텍스트 링크만 써서 금지 목록과 충돌 없음
- 보조 채택: 안 2의 해석 줄은 F1 다음 단계 후보로 보류, 예시 검색어를 상황 문장 형식으로 바꾸는 부분만 이번에 반영
