## 검색 범위 열: 이전248 및256+24 취소

원문 근거: `capture_map.md`의 G-02 대응은 `UX/handson/gitlab/44_전역검색_결과_hwp.png`다. 3840×2160 이미지는1920 CSS 폭의2배 캡처다. 검색 결과의 첫 행 x는 이미지 약1089px, CSS544.5px다. 기존248은 Figma 수치를 근거로 한 임시 판정이었으며 실제 열을 측정한 값이 아니었다.256+24 역시 실제 검색 구조와 다르다. 두 판정을 취소한다.

실제 공개 `/search?search=hwp`를1920/1440/1024에서 새로 읽었다. `.filters` 시각 상자는240px지만 왼쪽 margin -12px를 가진다. 부모 section이 차지하는 **논리 열은228px**, 결과와의 별도 열 간격은0이다. 그룹 선택216px와 시각 필터240px를 논리 열 폭으로 혼동하지 않는다. 증거: 세션tmp `M12-live-search.json`.

### 적용 명세

D-21의 바깥 여백·1200 최대 본문 폭을 유지한다. **공통 Search의 논리 열228, 열 사이0, 결과 x = 본문 x +228**로 코드와 Figma를 맞춘다. 실제의 음수 여백을 바깥 여백에 덧붙이지 않는다. 코드/Figma의 `filters` 이름표는 시각 박스240이 아닌 논리 열228에 붙인다. A-01과 G-02는 같은 Search 부품이며 다음 한 표를 공유한다.

|창 폭|본문 x/w|filters x/w|열 간격|results 및 project-row x/w|
|---|---|---|---:|---|
|1920|360 /1200|360 /228|0|588 /972|
|1440|120 /1200|120 /228|0|348 /972|
|1024|40 /944|40 /228|0|268 /716|
|768|32 /704|접힘|0|32 /704|
|360|16 /328|접힘|0|16 /328|

코드 전: `--layout-search-scope-w=248`, `.rb-s-body gap24`. 코드 후: 범위 열228, column-gap0.1920/1440/1024 결과 x632/392/312→588/348/268, 폭928/928/672→972/972/716. 새 실측에서 넘침0을 확인했다. Figma는256+24를 폐기하고 이 표로 재생성한다. 부모에게 동일 명세를 전달했다. 공식 다음 원장 재측정 전까지66행 해소로 세지 않는다.

## C2 표본

`M12_C2_samples.md`에20개 원인에서 한 행씩 추출한 표가 있다. 미수정17, Figma 담당3, 이미 수정했지만 매핑 오류로 남았다고 확인한 행0이다. 이 비율을279 전체에 외삽하지 않는다. M12는6d45848 측정이고 이후 도구 줄 메뉴 커밋은 C2 화면을 수정하지 않았다. D21 후보260을 C2 해소로 착각하지 않는다.

## 나머지 판정 주의

- M12의 실제 남은 코드 전용 tabs는 R27 Guest5건이다. M11의25를 현재 건수로 다시 쓰지 않는다.
- M12 page-head 높이는8건이다. M11의25는 현재 건수가 아니다.
- R25 section-title#3은 단순 y 보정이 아니다. 코드에는 커버리지 안내만 있고 Figma는 그래프 영역까지 차지한다. y만 밀거나 고정 여백을 추가하지 않는다.
- R07 section-title#2는 Figma에서 같은 머리글의 안쪽 글자를 다시 section-title로 붙인 중복 이름표다. 바깥 머리글은 유지하되 안쪽 텍스트 이름표를 제거한다. 이를 새 UI 절 누락으로 구현하지 않는다.
